## P0｜功能没闭环（业务价值没兑现，会员会实际踩坑）

### 1. 课程评价：只有会员端能用，**教练和店长都看不到自己的评分**
- **证据**：前端 `api/modules/review.ts` 里定义了 `getCoachReviewSummary()` 和 `getVenueReviewSummary()`，
  但**全项目没有任何页面调用它们**（搜遍 `.vue` 只命中定义处）。
- 后端接口是好的（`/coach/reviews/summary`、`/admin/reviews/summary`，平均分/五星分布/低分记录都算好了），
  会员端「课程评价」也能提交、能看自己的历史评价。
- **后果**：评分收上来了**没人看得到**。教练看不到自己几分，店长看不到门店汇总和低分预警 ——
  这个功能 90% 的业务价值等于没交付。导师如果问"收集评分做什么用"，现在答不上来。
- **建议**：① 教练工作台加「我的评分」（均分 + 星级分布 + 最近评价）；
  ② 管理端加评价汇总（各教练平均分排行 + ≤3 星低分记录），放「课程与排课」或经营看板。

### 2. 候补递补成功**不通知会员**
- **证据**：`BookingService` 里**一处通知调用都没有**（`grep notifications.` 为空）；
  递补逻辑 `next.setStatus("BOOKED")`（第 226 行）改完状态就结束了。
- **后果**：有人取消预约 → 候补第一位被自动补上位 → **会员完全不知道**。
  他没去上课 → 被记爽约（我做的过期核销还会把它变成 NO_SHOW），**会员体验和爽约统计双输**。
- **建议**：把预约事件接入已有的通知中心：递补成功、预约被取消、被记爽约/签到成功。

### 3. 会员提交退款后，**审核人不知道**
- **证据**：通知只挂在 `approve` / `reject` / `pay`（发给**申请人**）；
  `request(...)`（会员提交申请）里没有任何通知。
- **后果**：会员提交完以为在走流程，实际要等店长/总部**自己想起来**去翻「退款申请/审批」页。
- **建议**：提交时通知本店 + 总部有 `REFUND_APPROVE` 权限的人。

## P1｜角色定位与权限边界

### 4. 会籍顾问（SALES）这个角色**名不副实**
- **证据**：`SALES` 权限 = `MEMBER_READ, MEMBER_WRITE, ASSISTANT_USE, COUPON_READ, COUPON_WRITE`。
  - 没有 `SALE_WRITE` / `PRODUCT_READ` → **打不开「会籍与商业」，等于不能开卡卖卡**（会籍顾问的主职）；
  - 我给它的 `COUPON_READ/WRITE` **反而用不上**：优惠券页签在「会籍与商业」页里面，它进不去（这是 V11 我引入的不一致）；
  - **没有 SALES 演示账号** → 这个角色从来没有被验收过，属于"纸面角色"。
- **需要你定定位**：① 补 `PRODUCT_READ` + `SALE_WRITE` + `MEMBER_SELF_SERVICE`？
  （让它真能开卡卖课，但要考虑"谁能看会员的钱"）② 还是明确它只做"线索跟进 + 发券"，
  并把优惠券入口从「会籍与商业」里独立出来，让它进得去？

### 5. 会员（MEMBER）多了一个 `COURSE_READ`
- **证据**：`MEMBER = [COURSE_READ, MEMBER_SELF_SERVICE, ASSISTANT_USE]`；
  会员端全目录**没有任何** `/v1/admin/*` 调用（搜过），课程浏览走的是 `/member/schedules`。
- **后果**：因为这个权限，**会员能直接输 URL 打开管理端「课程与排课」页**（只读，写操作会被拒）。
  菜单虽然隐藏了，但按项目自己的纪律"前端菜单隐藏不算安全"。
- **建议**：从 MEMBER 去掉 `COURSE_READ`（先回归确认会员端不受影响）。

## 已核实**没有问题**的点（避免以后重复排查）

- **登录落地页正确**：`ROLE_HOME` 里前台/顾问落「会员管理」、教练落工作台、会员落会员中心，
  不会跳进无权限页；未知角色回落到「无权限」页而不是死循环。
- **店长无法提权**：`validateRoleCanBeCreated` 限制店长只能创建**教练和前台**账号，创建不了店长/超管。
- **教练能提交消课**：教练工作台里挂了 `TrainingPanel`（含提交、签课状态），不是只有管理端能提交。
- **前台能扫码核验入场**：「会籍与商业 → 扫码入场核销」面板在，支持扫码枪/粘贴二维码。
- **会员能自助取消预约**（含"开课前 2 小时内不可自助取消"的提示）。
- 所有 Controller 都有 `@PreAuthorize`；`/v1/finance/me/*`、`/v1/member/*` 都做了归属校验。
