# 六角色 AI 助手 V2 使用说明

当前为本地候选版本的使用说明。完整验收和日常启用状态见《AI助手V2升级进度_20261018》，不能把本文当作已经上线的说明。

## 六角色的使用范围

| 角色 | 可以交给助手的项目内工作 | 主要边界 |
|---|---|---|
| 总部管理员 | 授权跨店查询、准确课程改价、排课、预约签到、潜客与体验、回访、训练监督及消息 | 办理前仍核对门店与对象；不代教练创建或执行训练 |
| 店长 | 本店会员、课程、预约签到、潜客与体验、续费回访、训练监督及消息 | 保留本店隔离和原业务审批规则 |
| 前台 | 本店会员与排课查询、预约、签到、取消、交班日结只读及消息 | 不能修改课程定价或替顾问登记潜客跟进 |
| 教练 | 本人课程和服务学员、训练草稿、授权发布、执行记录及消息 | 按真实学员关系与服务门店；训练记录不等于签到、扣课或结算 |
| 会籍顾问 | 本人负责且本店的潜客、独立体验、跟进与回访及消息 | 独立体验和团课预约不同；不开放课程管理权限 |
| 会员 | 本人课程、预约与取消、训练与反馈、个人查询及消息 | 操作会员中心内部页签，不进入员工管理页面或读取别人档案 |

八组业务能力共用同一个当前网页执行框架。服务器仍检查原角色权限、关系和业务状态；表格描述实现范围，具体任务是否已通过完整验收以最终逐项成绩为准。

## 怎样描述任务

先把对象和目标说清楚，缺少编号时可以先查询。例如：

- “查询本周课程，再打开周课表。”
- “把翠湖店的流瑜伽课程价格改成 99，其他字段保持不变。”同名时补充查到的课程编号和名称。
- “为会员林晓雨预约流瑜伽，时间 2026-10-20 14:00。”同名会员或多节同名排课时补充准确编号。
- “为潜客张三登记电话跟进，内容：已介绍团课，结果愿意体验。”
- “为学员创建训练计划草稿，写明学员、标题、日期和动作组次，不发布。”
- “给指定联系人发送：明天下午到店后联系我。”同名联系人时使用准确用户编号并保留完整消息内容。

日期、姓名和课程仅为表达示例，实际使用应替换为当前有权查询到的对象。连续目标要说清顺序；“不保存”“不发布”“其他字段不变”等限制会作为目标约束保留。

## 提交和完成状态

助手直接操作当前 FitChain 标签页。页面切换、点击和填写在当前网页发生。

点击业务页面的保存或原生确定按钮后，真实业务请求会被冻结。助手显示实际对象、请求参数和变更，只有用户点击“确认并提交这一次”才办理该次业务。多次业务提交分别确认；确认整份计划不能替代每次实际提交。

“已完成”需要对应目标的服务端结果核验；打开页面、选中下拉值、模型说成功或某一个子目标成功，都不足以证明整个任务完成。“部分完成”保留已经成功的业务，剩余部分会单独显示。

同名、门店不符、名额不足或原业务规则拒绝时，助手应给出具体原因，不能猜测对象或绕开权限。

## 中断、补充与恢复

- 关闭助手、隐藏网页或断网会暂停。重新继续后，待提交业务仍须单独确认。
- 任务未结束时可补充要求。明确切换到另一对象时，建议用“改为任务：……”给出完整新目标；旧确认会失效。
- 刷新后按恢复入口重新取得当前网页租约；旧网页的许可不能继续使用。
- 重新登录后可以查看本人、同角色同门店的旧历史，但旧会话记录只读。需要办理新的业务时创建新任务。
- 提交结果不确定时先查回执和原业务结果，不能反复保存。人工接管会刷新当前页，请先留意未保存表单。

## 当前限制

助手限于项目注册的查询、页面动作和业务操作，不执行任意 JavaScript、SQL、Shell，也不操作其他桌面软件。收款、退款、开卡、账号凭据、交班和复核仍走原人工业务流程。

截图视觉输入尚未交付，当前使用 DOM、语义字段和真实业务查询。没有针对任意任务或其他商业 Agent 的等效承诺。任务具有执行、调用和 token 预算，超过预算会停止并保留实际结果，不应显示虚假的完成状态。

维护者可以通过全局和八业务组开关暂停新能力；正常业务数据不因回退助手而恢复旧备份。默认仅本地开发，服务器发布另行授权。
