# 前台交班与日结

第3项新功能：门店统一班次，每店同时一个进行中的班次；核对本店所有成功收款、退款，提交后由店长或总部独立复核。本轮在本地开发，本轮未连接或更新服务器，线上沿用上次验收记录。验收证据记录在 `qa/cash-shifts-20261010/verification.json`。

## 使用入口与操作

前台、店长和总部登录后，左侧进入 **交班与日结**。前台和店长只处理本店，总部可以选择任意门店。总部看全部门店时只能查看汇总，开班前需选具体门店。

1. **开班**：记录当班备注。一个门店已有进行中班次时，先完成该班；不能同时开第二班。
2. **核对流水**：查看当前班的系统收退款、渠道和逐笔记录。首次开班以前的历史流水保留在原财务报表，不自动归入首班；后续班次包含上一交班后、当前开班前的待交班流水。
3. **逐渠道填写实际金额**：现金、微信、支付宝、银行卡以及流水中出现的其他渠道，都需明确填写实际收款和实际退款。初始为空；没有金额时填写 `0`。本期登记实际收退款合计，备用金和钱箱余额不参与计算。
4. **提交交班**：任何渠道的收款或退款有差异，都必须说明原因，即使两个差异相抵、总净额恰好一致。提交前又登记了流水时，需要重新载入并核对。
5. **店长复核**：另一位店长或总部可以通过或填写原因退回。最后提交交班的人不能审核自己的班次。已提交后可以开下一班，不必等审核。
6. **退回修正**：原开班者、上一提交人或管理者修正实际核对数并重新提交；原系统金额和逐笔流水保持固定，修改留有审计记录。

## 查看日结

营业日按 **开班时的上海日期** 计算；跨午夜提交仍归开班营业日。原财务报表按流水发生日计算，两者用途不同。

日汇总对已提交、退回和已复核的班次各计算一次；进行中班次的实时预览不计入已交班金额。页面单独显示已复核净额，待审核、退回班次仍需处理。状态筛选和分页只改变列表，不改变当天汇总。

退款允许补录过去的发生时间。本功能按新登记流水归班，因此补录的退款会进入本班或下一班，不会因发生日期早而遗漏。已经提交的班次不会吸收后来的流水。

`SELF_SERVICE` 指现有会员自助购买登记，当前系统尚未接入支付平台；核对时需核实实际收退款，页面和审批不会自动证明银行到账。

## 开发与扩展约定

- 新模块 `module/cashshift`，新入口 `/cash-shifts`，接口 `/api/v1/cash-shifts`；原开卡、续费、退款、权益和财务报表继续使用原流程。
- V21 新增四张表：`cash_shift`、`cash_shift_channel`、`cash_shift_payment`、`cash_shift_event`。V1—V20 不修改；第一次开班不补写历史资金。
- 整数分计算，实际金额非负、最多两位小数；净额及差额允许负值。快照、版本、权限和请求重复保护均由后端校验。
- 本店的资金登记与交班边界复用门店事务锁；每店最多一个进行中班次，逐笔流水只能归入一个已交班快照。
- 此后接入支付对账、现金钱箱或多岗位交接，应新建明确的资金口径和迁移，不改写既有快照。
- 本地测试使用隔离数据库；真实会员、订单和收退款不写入验收测试资料。默认验收桌面布局。
