## 已修复行为

1. 新售订单按商品发卡门店，续费订单按原权益发卡门店记账；资金来源、权益与订单归属一致。总部跨店销售后可以正常走退款申请。
2. 教练的管理预约列表仅含本人排课；所有预约管理响应改为必要字段 DTO。保留前端使用的 `member.realName/memberNo`、`schedule.course.name`、教练名、时间与状态，不返回手机号、身份证、地址、用户关联或永久入场令牌等会员档案。
3. 扫码选择和锁后重验均检查实际权益的门店范围快照；只能消费覆盖当前入场店的卡。
4. 续费要求显式幂等键，复用 `sales_order.operator_id + idempotency_key + request_fingerprint`。指纹包含操作、权益、追加天数/次数、金额、支付方式和备注；操作者行锁串行处理同操作者请求，重放不会再次增加订单、流水或价值余额；相同键配不同内容拒绝。
5. 新售指纹包含会员券 ID，避免无券改有券、券 A 改券 B 被旧单静默复用。
6. 退款清理阻断项门面显式 `NOT_SUPPORTED`；每条 BookingService 代理调用独立事务。一条后续取消失败不会回滚此前已成功取消。
7. 会员本人的跨店购买、预约、候补递补、取消和私教签课按本人身份与权益范围快照处理；员工管理仍按门店范围。跨店授权排除尚未开始、日期已过期或次数耗尽的 ACTIVE 权益。
8. 会员跨店自助退款使用独立 `lockForCurrentMember`，锁前锁后均核验本人，锁仍在发卡门店；员工 `lock/assertScope` 原边界保留。本人可以报价、申请、重放、撤回；不能办理他人权益。
9. CommercialCenter 保留既有外观，续费同一内容重试保留键，进行中的重复点击忽略，内容变化或成功后的新意图生成新键。原续费测试均增加显式键，原资金断言保留。

## 独立审查后的补充修复与最终验证

独立审查确认两项 Important 与一项指纹歧义，均以真实回归先复现再修复：

- A 店会员券不能抵扣 B 店发卡订单。`CommercialService` 的用券校验和失败解释均按商品发卡门店；`CouponService` 的跨店商品报价按同一范围与门店校验，合法跨店商品可报价、A 店券不在 B 商品可用列表，普通员工管理报价仍保留门店范围。
- 新增团课预约、候补、销售和开始退款先取得稳定的会员服务行锁，顺序为会员 → 门店 → 排课/权益。会员本人退款锁也先取得该锁；员工退款起点同样参与，不改变员工 scope。PostgreSQL 使用 `FOR NO KEY UPDATE`，避免阻断其他资金操作的外键 `KEY SHARE`；H2 使用悲观行锁。既有候补递补从 WAITLISTED 变为 BOOKED，始终属于退款阻断项，未在递补中引入晚获取其他会员锁。
- 销售与续费指纹采用固定字段顺序的 JSON 序列化后 SHA-256，文本中的 `|` 不再造成字段歧义；金额去除尾随零，20.00 与 20.0 的同内容重试可重放。
- 四个真实事务并发回归：会员退款先行与团课、会员退款先行与候补、员工退款先行与团课、预约校验完成但事务未提交时退款。Spy 仅控制真实方法边界的时序，不替换业务判断、数据库写入或事务。退款先行断言退款必须成功、新服务必须拒绝；预约先行断言预约必须成功、退款必须拒绝，避免双超时都失败的伪通过。
