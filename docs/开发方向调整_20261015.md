## 推荐方案

### 移动端

采用同一 Vue 工程中的手机 H5 界面，复用登录、后端接口和业务规则，逐步增强为 PWA。手机使用底部导航、列表卡片、适合触控的表单与全屏助手，保留现有桌面布局。

六角色均有手机入口，先完成会员和教练的高频路径，再覆盖顾问、前台、店长和总部的主要任务。完整管理功能按具体页面适配，不把现有桌面大表格简单缩小。

PWA 添加桌面能力依浏览器和平台而异，需要 HTTPS 或符合条件的 localhost 开发环境。手机通过电脑局域网 IP 访问并不享有电脑 localhost 的安全例外。首版不做离线业务提交、不缓存账号或会员敏感数据；离线时明确提示无法提交。

### 六角色 Agent

共用一套服务端 Agent 引擎，分别配置角色任务、允许使用的工具和上下文范围，不建设六套互相独立的后端。

| 角色 | 推荐首批能力 |
|---|---|
| 总部管理员 | 跨店经营查询、数据比较、异常汇总、生成可核验的报表 |
| 店长 | 本店运营待办、会员风险查询、准备排课方案与交班复核资料 |
| 前台 | 查询课程余量、为指定会员准备预约、查询预约与交班资料 |
| 教练 | 查看本人安排与授权学员资料、生成训练计划草稿并确认保存 |
| 会籍顾问 | 查询本人且本店的临期会员和潜客、准备体验预约与联系安排 |
| 会员 | 查询本人课程、预约、权益与训练记录，确认后预约或取消 |

查询直接返回有来源和时间范围的真实数据。写入业务先生成明确的操作预览，用户确认后由服务端重新鉴权、校验最新数据并执行，最后返回真实业务结果。退款、签课、付款和结算保留现有审核及真实事实要求，首批不扩展为自动财务执行。

模型只能调用白名单业务工具，不能自行访问数据库、运行任意代码或通过对话切换角色。接收的外部文本和模型输出均不视为操作授权。任务应具备参数校验、幂等、执行审计、步数上限、超时和失败说明；退出或切换账号后不得继续执行旧确认。

DeepSeek 官方 API 提供 Tool Calls，但本项目实际接入的网关、模型及配置仍需用不写业务数据的契约测试验证。服务不可用时保留帮助与页面操作入口，不伪造执行结果。

## 实施里程碑建议

1. 核对实际模型的工具调用兼容性，确定手机端导航与六角色工具权限矩阵。
2. 完成六角色手机工作台骨架，以及会员约课、教练查看计划等高频场景。
3. 为六角色接入真实只读工具，加入数据来源、会话隔离与服务状态展示。
4. 打通首批受控写入：会员预约、顾问体验安排、教练训练计划草稿，展示预览、确认与执行回执。
5. 扩展其余角色的必要操作并验证跨店隔离、并发重放、模型异常和手机/桌面兼容。

本轮为两个相互关联的新子系统，重新分阶段估算；原器械维护的3–4天计划不适用于此次范围。

## 验收与执行边界

- 本阶段用户明确提出移动端，因此包含手机布局及可用真机验收；桌面原有功能仍需回归。
- 模型或工具失败不得显示成功；预约成功必须对应真实记录；草稿与已生效业务明确区分。
- 每个角色均验证允许操作与越权拒绝，测试写入只使用隔离库。
- 已应用迁移字节不改写；需要持久化会话和执行审计时新增递增迁移。
- 默认本地开发；实施阶段已进行隔离模型协议请求（401），没有连接服务器、推送或发布。后续只有用户明确要求更新服务器时才上线。
