## 已修复问题

| 问题与触发条件 | 修复后的行为 |
|---|---|
| 刷新令牌可被当作访问令牌；停用、删除、降权、调店后旧访问令牌继续有效 | 区分令牌用途，每次请求核对数据库现时身份、状态、角色、范围和会话版本；安全变更立即撤销旧访问及刷新令牌 |
| 登录记录更新与重置密码并发，旧快照可能覆盖新密码和版本 | 登录先锁账号再认证；安全变更共用账号锁，实体仅更新变化字段 |
| 退出不能服务端撤销，访问过期时退出无效；迟到退出会影响同账号新登录 | 每次新登录独立 `sid`，退出持久化撤销该登录；前端捕获 access/refresh 后清理本地状态，支持访问已过期；其他设备仍可用 |
| 旧格式刷新绕过退出，或已经退出的改密码请求重新签发会话 | 旧格式刷新保留无 sid，退出按账号版本撤销；改密码取得锁后再次检查版本与 sid 撤销状态，返回可用替代会话 |
| 退出或切换账号后，旧刷新成功/失败覆盖新状态或跳转新账号 | 请求、刷新、导航绑定会话代次；迟到结果不能恢复旧会话、清理新会话或借用新账号令牌 |
| 聊天 A/B 响应乱序导致显示与发送对象不一致；卸载后异步创建轮询 | 联系人、草稿、发送与回包绑定同一目标；账号变化或卸载后丢弃结果，不再创建定时器 |
| AI 助手合法长文本使下一次历史请求超限 | 保留显示内容，提交历史限定最后 6 条，每条最多 500 字符 |
| 无会话时可直接查询不允许联系的账号身份 | 首次读取线程必须符合联系人规则；本人已有历史会话仍可阅读，新的发送继续验证当前关系 |
| 总部跨店售卡/续费产生订单与权益不同门店，后续退款账无法对应 | 新订单及资金来源按商品/权益发卡门店归属；既有历史账不自动改写 |
| 教练预约列表包含同店其他教练，预约响应带出整份会员隐私字段 | 教练仅查询本人排课预约；接口使用必要字段 DTO，保留页面所需信息 |
| 跨店扫码准入与实际扣卡选择不同，可能扣掉不覆盖该店的卡 | 选卡及锁后复核覆盖范围、状态、有效期、余额，扣除实际可用权益 |
| 续费重试重复收款/增加次数；优惠券未进入销售指纹；分隔符指纹碰撞 | 续费携带同一次意图的幂等键，服务端锁定重放；销售/续费采用结构化完整指纹和规范化金额，不同内容拒绝复用 |
| 普通会员可看跨店服务，却不能购买、预约、候补、取消或确认私教 | 本人消费依据有效权益快照；本人跨店退款有独立所有权锁入口，员工管理门店范围仍受限制 |
| A 店券可经购买接口抵扣 B 店商品，报价与下单不一致 | 报价和购买统一按商品销售门店验证优惠券；跨店购买资格与券使用资格分别校验 |
| 跨店退款与新增预约/候补各锁不同门店，可能并发双成功 | 新增服务和退款统一先锁会员，再锁门店/权益；PostgreSQL 使用 `FOR NO KEY UPDATE`，保留外键检查兼容性 |
| 批量取消退款阻断预约，一条失败回滚全部成功项 | 取消门面不包外层事务，逐条通过独立事务执行，保留成功项并报告失败项 |

前后端认证错误日志不再打印原始请求异常，避免调试日志带出令牌。撤销表的过期记录接入既有定时清理，应用重启保留未过期撤销记录。V18 为新增迁移，已发布的 V1–V17 未修改。

2. **核对历史跨店资金归属**：新代码阻止继续产生订单/权益门店错配，但不追溯改写旧账。上线前应只读筛查历史异常，结合原凭证人工确认处理方案。
3. **拆分前端公共包**：当前最大主包约 1.19 MB（gzip 约 383 KB），存在构建体积警告。后续按实际加载分析拆分 Element Plus 等依赖；未通过隐藏警告宣称性能已解决。
4. **跨店服务标明上课门店**：会员聚合排课/预约目前缺少清晰的门店名称，建议补充地点信息，避免会员误到店。
5. **持续维护与备份验证**：定期复查依赖、验证离机备份可恢复。现有生产应用日志已经配置 20 MB / 30 天 / 1 GB 轮转；本轮未核验服务器其他日志和备份计划的实际状态。
