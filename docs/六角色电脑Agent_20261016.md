# 六角色电脑 Agent 首版（本地）

本轮在原业务问答、业务工具之外，加入真正的受控浏览器执行循环：描述目标 → 观察页面 → 模型规划一步 → 实际点击或填写 → 读取反馈 → 继续。总部管理员、店长、前台、教练、会籍顾问、会员共用执行器，各自保留现有首页、权限和门店范围。

## 使用方法

1. 双击仓库的 `start.bat`。它会启动原服务，并尝试启动本机电脑执行器；首次需要安装执行器依赖。电脑需已安装 Edge 和 Node.js 24。
2. 从运行项目的这台电脑打开 `http://localhost:5173/login`，登录自己的角色账号。
3. 打开右下角助手，在“会话”选择“电脑执行”，直接描述目标。任务会出现在“电脑任务”，另开独立 Edge 窗口实际操作。
4. 可查看步骤和最新截图，点击“暂停”“继续”“停止任务”；缺少资料时在面板补充。关闭助手只隐藏面板，不会取消任务。
5. 操作表单时，执行器会冻结实际业务请求，显示字段供核对。只有点“确认并提交这一次”后才放行这一条请求；后续提交仍需再次确认。

可尝试：“打开周课表，查看本周课程”“打开潜客与体验课，查看我的潜客”“点击我的训练，查看自己的训练计划”“导出本周本店可见课程，生成 CSV 课表文件并打开”。新建档案等任务应提供明确对象和必要资料，保存前仔细核对确认预览。

成果默认写入桌面 `FitChain任务成果` 文件夹。首版只生成新的课表 CSV，不覆盖已有文件；显示文件名、字节数和 SHA-256。打开使用系统记事本，回执为“已请求 Windows 打开文件”，不冒称已验证文件窗口。

## 当前能力和限制

- 可操作当前角色允许的 FitChain 页面：导航、观察、点击、填写、原生选择、自定义下拉选项、单选框、滚动、返回。使用最新页面元素引用，禁止模型执行任意代码、Shell 或自行构造业务 API。
- 根据真实工具回执继续规划；同任务相同日期范围不重复生成文件，同一成果不重复启动查看窗口。生成了文件但没有请求打开时，不能把“生成并打开”任务报为完成。
- 使用独立临时浏览器上下文，不接管私人浏览器资料；任务绑定账号、角色、门店及登录会话。退出或切换后，旧任务不能被新身份读取或确认。
- 本机同时一个活动任务，最多 30 步、总计 10 分钟，等待确认/补充/暂停最长 5 分钟。默认模型步骤间隔至少 8 秒，以适配现有服务调用限额。无效模型规划最多重新观察两次，不自动重放业务写请求。
- 模型服务异常、业务拒绝、结果不确定会明确失败；已确认请求发送后发生中止或超时，要求人工核对，不自动重试。
- 用户提供的手机号、邮箱、证件号在任务中先换成本地资料引用，填写时才由执行器还原；后台模型传输继续执行既有隐私脱敏。模型密钥只留在后台受保护配置中。
- 会员课表导出沿用“可预约课程”数据，限定本人服务门店中当前之后的可预约排课；不是本人历史预约/出勤清单。过去日期可能返回空记录。员工导出按现有角色查询范围，不提升权限。
- 首版仅 Windows 本机 `localhost` 入口提供电脑执行。手机/LAN 继续使用原业务助手，不获得宿主机控制权；正式静态部署未接入本机桥接。当前没有任意 Windows 软件自动化或截图视觉理解。
- 列表复杂、信息不明确或控件未支持时可能需要补充或人工接手，不承诺任意一句话都能自动完成。

## 维护入口

| 模块 | 位置 |
|---|---|
| 角色身份和单步模型规划 | `fitness-backend/.../module/agent/computer/` |
| 本地执行器及浏览器/文件边界 | `fitness-agent-runner/src/` |
| 会话切换、任务面板 | `AssistantPanel.vue` / `ComputerAgentPanel.vue` |
| 本机桥接 | `fitness-frontend/dev/local-agent-bridge.mjs` |
| 启动与私有配置 | `scripts/start-local-agent.ps1` |
| 设计/实施记录 | `docs/superpowers/specs/2026-10-15-computer-agent-design.md` / 对应 plan |

执行器只监听 `127.0.0.1:5188`。随机桥接凭证保存在当前用户 LocalAppData 私有目录，前端不保存该凭证。桥接检查回环来源、Host、Origin 和工程指纹；启动不会终止无法证明属于当前项目的端口占用者。后台会在每步及确认发送前重新验证当前身份；冻结请求不能换参，重复确认不重复发送。不可完整预览的过大/过深请求直接拒绝，改由人工界面处理。

只读 POST 例外仅有现有 Agent 查询工具，以及经过角色、路径和参数校验的会员课程推荐；它们不创建预约或订单。其余非 GET/HEAD/OPTIONS 请求均进入确认门槛。

运行记录见 `docs/qa/computer-agent-20261016/verification.json`、六角色模型任务 JSON、桌面完整流程 JSON 及截图。测试写入只在显式标记的独占 PostgreSQL 隔离库进行。正常本地启用需先备份并校验迁移、业务数量与密码哈希；本轮不更新阿里云。

规划协议使用非思考模式下的 `tool_choice=required`，普通业务问答保持 `auto`；参考 [DeepSeek 对话补全接口](https://api-docs.deepseek.com/api/create-chat-completion/)。历史动作在前，最新观察以工具回执放在后；元素引用短小且每次观察更换，避免过时引用。模型输出仍经过后台与执行器双重校验，调用工具本身不代表业务成功。
