## 🔴 一、门店隔离漏洞（4 条，全部出在我最近写的代码里）

### 1. 经营分析的教练绩效没按门店过滤
- **位置**：`module/analytics/service/AnalyticsService.java:108`（`lessons.findAll()`）、`:122`（`reviews.findAll()`）
- **现象**：会员与预约都是按门店取（`scopedMembers()`），但**私教课时/产值、评价统计是全库取**，教练名单由这两者拼出。
- **影响**：**店长**在「经营分析」看到**其它门店教练**的私教产值与评分（超管看全量属预期）。
- **修法**：按门店范围过滤教练（本店 `sys_user.venue_id`），或先用 scoped 数据取出本店教练 id 再过滤。

### 2. 商品「跨店适用范围」接口没有商品归属校验
- **位置**：`module/commercial/controller/CrossVenueController.java:30-40`
- **现象**：只校验 `PRODUCT_READ/PRODUCT_WRITE`，随后直接 `products.findById(id)` 就改，**没有 `CommercialService.accessibleProduct()` 那样的门店校验**。
- **影响**：**店长**可用任意商品 id 读/改**别店商品的适用门店范围**。前端只会传本店商品，所以要靠构造请求触发（真实缺口）。
- **修法**：改成走 `CommercialService.accessibleProduct(id)`，或补同样的门店断言。

### 3. 消息投递记录没按门店过滤
- **位置**：`module/message/repository/MessageDeliveryRepository.java:9` → `service/MessageDispatchService.java:44`
- **现象**：`findTop100ByOrderByIdDesc()` **没有 venue 条件**（实体里有 `venueId`，但只用来留痕，没参与过滤）。
- **影响**：**店长/前台/会籍顾问**在「消息与渠道」看到**全部门店**的投递记录（收件人已脱敏，但标题/内容片段可见）。
- **修法**：按 `getCurrentOrganizationId()` 过滤；超管看全部。

### 4. 手动发消息不校验会员门店
- **位置**：`module/message/service/MessageDispatchService.java:49-53`
- **现象**：`sendToMember()` 只按 id 取会员，**没校验会员所属门店**。
- **影响**：有 `MEMBER_WRITE` 的**店长/前台/顾问**可给**任意门店会员**派发消息。
- **修法**：补会员门店校验（超管放行）。

## 🔴 二、"编辑会员会静默清空归属人"（1 条，会击穿昨天刚做的顾问/教练功能）

- **位置**：`fitness-frontend/src/views/admin/MemberList.vue:212-222`（`openEdit` 手工拼字段，**漏了 `coachId`/`salesUserId`**）；
  后端 `module/member/service/MemberService.java:106-107` 会把请求里的 null 直接写库。
- **现象**：打开"编辑会员"时两个归属下拉是**空的**（不回填），保存时**也没带这两个字段** → 该会员的「专属教练 / 会籍顾问」被**清空**。
- **影响**：店长/前台只要编辑任何会员，就会把归属抹掉 →「会籍工作台：我的会员」「教练：我的学员」直接变空。
- **证据**：`MemberResponse` 里**本来就有** `salesUserId/coachId`（`dto/MemberResponse.java:21-22`），所以后端是支持回填的，纯粹是前端漏了。
- **修法**：`openEdit` 补上 `coachId/salesUserId`（和昨天修"教室没存进去"是同一类 bug —— 手工拼字段）。
- **补充**：同类隐患要一起排查 —— **凡是"手工拼请求体"的地方，加字段时必须同步**。

## 🟡 三、角色权限口径不一致（3 条）

### 5. 教练能看到"全店"教练评分与低分评价内容
- **位置**：`security/RolePermissionCatalog.java` COACH 含 `COURSE_REVIEW_READ`；`review/controller/ReviewController.java:49-53` 的 `/admin/reviews/summary` 用该权限放行，返回**本店各教练平均分 + 低分记录**。
- **现象**：本意是"教练看自己"，但教练拿到这个权限后能调**店长视图**的接口；前端 `CourseManagement.vue` 的评价汇总也随之渲染出来。
- **修法**：教练只保留 `/coach/reviews/summary`（`COACH_WORKBENCH` 已放行），从 COACH 权限里去掉 `COURSE_REVIEW_READ`；店长视图自然只剩店长/总部。

### 6. 会员多余的 `COURSE_READ`，导致会员端菜单露出管理页面并"一进就 403"
- **位置**：`security/RolePermissionCatalog.java:98`（`MEMBER = COURSE_READ, MEMBER_SELF_SERVICE, ASSISTANT_USE`）；
  前端会员端**挂在 `AdminLayout` 下**（`router/index.ts:26,98`），菜单按权限过滤（`AdminLayout.vue:60-61,71`）。
- **现象**：会员登录后菜单里出现**「课程与排课」「周课表」**；点进去后页面初始化会调 `listCoaches()`，而该接口要求 `SCHEDULE_WRITE` → **加载即弹 403**。
- **修法**：从 MEMBER 权限里去掉 `COURSE_READ`（会员看课程走会员端 `/api/v1/member/...`），一处改动同时解决"菜单露出"和"403 弹窗"。

### 7. 前端路由守卫不校验 `meta.roles`
- **位置**：`router/index.ts:106` 声明了 `roles:['SALES']`，但 `:135-138` 的 `beforeEach` **只校验 `permissions`**。
- **现象**：`/advisor-workbench` 只要 `MEMBER_READ` 就能用 URL 直接进（菜单靠 `AdminLayout` 的 `roles` 才隐藏）。后端 `AdvisorService.workbench()` 按"我"过滤，**不泄露数据**，但"菜单/路由/后端"三处口径不一致。
- **修法**：守卫里补 `roles` 校验（几行）。

## ⚪ 四、功能缺陷与体验（3 条）

### 8. 报表三个接口完全忽略入参
- **位置**：`module/report/controller/ReportController.java:28-44`
- **现象**：`venue-performance?venueId=`、`coach-workload?coachId=`、`sales-performance?salesId=` **都直接返回 `dashboard()`**，入参从未使用。
- **影响**：接口名与行为不符（属既有遗留）。不越权（`dashboard()` 已限本店），但功能是空的。
- **修法**：要么实现，要么删掉这三个空接口（避免误导）。

### 9. 教练工作台点「体测」对"非专属学员"会失败，且失败时显示成空态
- **位置**：前端 `views/coach/CoachWorkbench.vue:25,68`（学员来自**排课预约**）；
  后端 `module/member/service/BodyMeasurementService.java:192-196`（COACH 分支要求 `member.coach_id == 本人`）。
- **现象**：团课学员通常没把该教练设为"专属教练" → 点「体测」→ 服务层拒绝（200+1003），而 `BodyMeasurePanel` 没有错误处理 → 界面显示「还没有体测记录」，**像是没数据，其实是没权限**。
- **修法**（二选一）：① 放宽为"该教练任意排课上的学员均可查看/代录"；② 前端在该场景隐藏按钮并说明原因 + 面板补错误态。

### 10. 两处前端兜底缺失（低）
- `views/coach/CoachWorkbench.vue:22`：`row.realName.slice(0,1)` —— 姓名为空会直接报错。
- `views/admin/Analytics.vue:75-84`：`Promise.all` 任一失败整页空白（无错误态）；`onMounted` 的 Promise 未 catch。
- `components/BodyMeasurePanel.vue:159-164`：加载失败无错误提示。
