## 本轮解决的问题

| 问题 | 修复与验证 |
|---|---|
| 补充价格时丢失“不要提交”，或把换对象误当改数值 | 保留剩余约束；切换目标必须明确完整任务，旧许可失效。先复现失败，再通过回归。 |
| 同名跨店对象、预约会员与时间绑定不足 | 准备提交前核对原权限范围内的唯一编号、门店、会员及排课时间；不唯一时要求明确编号。创建潜客及删除课程的遗漏也已补测。 |
| 旧跟进回执冒充新的资料修改结果 | 同时核对具体操作类型、当前目标字段、新增事件与原业务查询结果；只有对象编号相同不能判完成。 |
| 训练记录超过第一页后回查失败 | 在原访问规则下按准确记录编号读取；新增训练从同一事务的实际事件取得记录编号，原业务接口仍保持分页返回。真实业务集成用例验证了 21 条记录中最旧记录的反馈和其他会员的拒绝。 |
| 重新登录看不到旧任务 | 历史查看仍按本人、角色和门店隔离；旧会话记录只读，不能恢复其执行与确认许可。真实 Vue/HTTP 测试通过，未调用模型或写入业务。 |
| 预约反复查人、反复选择已选对象 | 识别原会员接口的 `items` 分页；只保留用户精确查询姓名用于定位；字段增加已选编号，并按编号判断是否已填写。 |
| 自定义下拉框与模型动作不匹配 | 通用 `select` 动作通过同一个控件适配器操作 Element Plus；内部只读输入不再误报为整个下拉不可选。保留过期引用、禁用状态、弹窗与任务状态检查。 |
| 已选下拉值被误读为空、训练表单归属错误 | 读取实际显示的选中值，排除隐藏输入层；用明确的表单身份代替第一个候选学员，补齐学员及日期字段。真实 Element Plus 和应用页面复测通过。 |
| 规划响应丢失后报错或重复推理 | 相同任务、版本、网页和请求内容可短时取回同一响应；前端仅重连规划接口，业务和审批不自动重发。真实丢响应测试：两次 HTTP 请求、一次模型调用、零业务写入、同一网页。 |

## 回退开关

`AI_TASK_V2_ENABLED` 控制 V2 内核，`AI_PLANNER_THINKING_ENABLED` 控制规划思考模式。

`AI_TASK_DISABLED_SKILLS` 可填逗号分隔的业务组：`navigation,messages,courses,members,leads,retention,training,operations`。业务组关闭后，V2 对应查询和业务许可被拒绝；导航组关闭时拒绝切页、返回及页面点击。原手动业务入口保留，旧许可不能借关闭开关继续提交。开关只增加限制，不改变原角色权限。
