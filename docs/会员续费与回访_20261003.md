# 会员续费与回访（第 1 项，2026-10-03）

本地已开发并启用。打开项目后，在左侧进入 **续费与回访**；会籍顾问工作台也有入口。本轮只开发用户批准的第 1 项，第 2–5 项尚未实施；未连接阿里云、发布或推送。

## 操作方式

1. 优先查看“逾期回访”和“今日回访”，再筛选“7 天到期”“30 天到期”或“高风险”。姓名、会员号、手机号可搜索；总部和店长也可按顾问姓名搜索。
2. 在会员卡片点击“记跟进”，填写沟通方式和内容，选择未联系上、已约到店、考虑续费、暂不续费或其他；可约定未来的下次联系时间。
3. 保存后任务与最近跟进自动更新；“跟进记录”保留完整历史。未填写下次时间表示本次没有安排下一次联系。
4. 实际办理续费仍进入原有“会籍与商业”流程。本页中的“考虑续费”仅记录沟通进展，不能生成订单、改变会籍或标记已成交。

## 数据范围与统计口径

| 项目 | 规则 |
|---|---|
| 会籍顾问 SALES | 只看本门店归属自己的会员；不能借用历史教练归属查看或新增其他顾问的记录 |
| 店长 MANAGER | 只看所属门店会员、回访与顾问概览 |
| 总部 SUPER_ADMIN | 查看各门店会员与顾问概览 |
| 前台、教练、会员 | 不开放新增续费与回访页面；原有功能沿用既有权限 |
| 今日回访 | 最新跟进约定的联系日期等于上海当天；同一天早于当前时刻也归今日 |
| 逾期回访 | 最新约定的日期早于上海当天 |
| 7/30 天临期 | 从今天起含第 7/30 天；按当前有效、有剩余次数（如适用）的权益最早到期日统计；门店角色不展示外店权益 |
| 高风险 | 复用已有可解释风险规则，页面展示风险原因；不新增 AI 判定或自动修改会员状态 |
| 本月已跟进 | 本月已记录跟进的会员去重人数，反映记录过沟通尝试，不冒充成功联系人数 |
| 本月实际续费 | 本月付款的 RENEW 订单，状态 PAID/PARTIALLY_REFUNDED 且实收减退款大于零；会员去重，净额累加；门店角色只统计本店订单 |
| 未分配顾问 | 店长/总部概览独立显示未分配组，不自动分配会员 |
| 搜索与筛选 | 只改变下面的会员列表；顶部指标与顾问概览仍表示整个权限范围 |

续费人数属于当前会员归属范围内的实际订单事实，**不是顾问个人销售提成或归因业绩**。全额退款订单不再计入；该页面不创建支付交易、不纠正历史账。

## 兼容、时间与扩展

- 新增 Flyway **V19**，仅为跟进表增加结果、提交标识与请求指纹及约束。历史记录结果默认 `NOT_RECORDED`，原内容和时间保留；V1–V18 未修改。
- 原跟进接口保留，旧客户端不提交 outcome 时仍可写入未记录结果。新版页面提交幂等键，后端在会员锁内查重；相同内容重试返回原记录，修改内容却复用同一键会拒绝。保存期间锁定表单和目标会员。
- 响应丢失后，相同请求即使约定联系时间已经经过也能重试；新请求或编辑后的请求仍要求未来时间。会话变化、页面卸载和过期响应不会发布旧数据或遗留草稿。
- 现有数据库 TIMESTAMP 使用上海本地时间。应用在 Spring/Hibernate 初始化前固定 JVM 时区，写入和统计统一为 `Asia/Shanghai`；历史时间不改写。权益到期属于日期，前端只显示日期。
- 独立 `/api/v1/admin/advisor/retention` 聚合接口与页面组件可继续扩展；所有业务查询先限定会员与门店范围，批量取得关联数据。更大数据量下可再增加服务端分页与汇总查询。
- 保留既有冰蓝主题和动效设置；新增页说明文字、标签和按钮加深，手机采用单列会员卡片与自适应弹窗。
