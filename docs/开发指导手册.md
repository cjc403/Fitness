# 健身房管理系统开发指导手册

## 一、项目架构说明

### 1.1 整体架构

本项目采用前后端分离架构：
- **后端**：Spring Boot RESTful API服务
- **前端**：Vue3 + Element Plus单页面应用
- **数据库**：PostgreSQL关系型数据库
- **认证**：JWT Token无状态认证

### 1.2 技术选型理由

| 技术 | 选型理由 |
|------|---------|
| Spring Boot 3.3.13 | 最新稳定版本，与Java 17完全兼容，提供现代化配置 |
| QueryDSL | 类型安全的查询构建，适合复杂查询场景 |
| Flyway | 版本化数据库迁移，便于团队协作 |
| Vue 3 | Composition API，更好的类型支持和性能 |
| Element Plus | 成熟的Vue3 UI组件库，快速开发 |

## 二、环境搭建指南

### 2.1 开发环境准备

#### 后端环境
1. 安装JDK 17
2. 安装Maven 3.9+
3. 安装PostgreSQL 16
4. 配置IDE（推荐IntelliJ IDEA）

#### 前端环境
1. 安装Node.js 18+
2. 安装npm或yarn

### 2.2 数据库配置

1. 创建数据库：
```sql
CREATE DATABASE fitness_db;
CREATE USER fitness_user WITH PASSWORD '<你的数据库口令>';
GRANT ALL PRIVILEGES ON DATABASE fitness_db TO fitness_user;
```

2. 配置连接（`application.yml`）：
```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/fitness_db
    username: fitness_user
    # 口令不入库、不写进文档：通过 DB_PASSWORD 环境变量注入
    password: ${DB_PASSWORD}
```

### 2.3 项目配置

#### 后端配置
- 配置文件：`src/main/resources/application.yml`
- 开发环境：`application-dev.yml`
- 生产环境：`application-prod.yml`（使用环境变量）

#### 前端配置
- 环境变量：`.env.development`、`.env.production`
- API基础URL：`VITE_API_BASE_URL`

## 四、开发规范

### 4.1 代码风格

- **Java**：遵循Google Java Style Guide
- **TypeScript/Vue**：使用ESLint + Prettier格式化

### 4.2 命名规范

#### 后端
- 类名：PascalCase（如 `MemberController`）
- 方法名：camelCase（如 `getMemberById`）
- 常量：UPPER_SNAKE_CASE（如 `MAX_SIZE`）
- 包名：小写，单词间用点分隔

#### 前端
- 组件名：PascalCase（如 `MemberList.vue`）
- 变量/函数：camelCase
- 常量：UPPER_SNAKE_CASE

### 4.3 Git提交规范

使用Conventional Commits规范：
```
feat: 新功能
fix: 修复bug
docs: 文档更新
style: 代码格式调整
refactor: 重构
test: 测试相关
chore: 构建/工具相关
```

示例：
```
feat(member): 添加会员暂停功能
fix(booking): 修复预约时间冲突问题
```

## 五、API开发规范

### 5.1 统一返回格式

所有API接口统一使用 `Result<T>` 封装：

```java
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2024-01-01T00:00:00"
}
```

分页返回：
```java
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "page": 1,
    "size": 10,
    "total": 100
  }
}
```

### 5.2 错误码规范

- 成功：0
- 系统错误：1000+
- 认证授权错误：1100-1199
- 业务错误：2000+

### 5.3 接口路径规范

- 管理端：`/api/v1/admin/{module}/{resource}`
- 会员端：`/api/v1/member/{module}/{resource}`
- 教练端：`/api/v1/coach/{module}/{resource}`

### 5.4 客户端错误与 HTTP 状态码映射

`GlobalExceptionHandler` 把可预期的客户端错误映射到对应 4xx，只有真正的服务端故障才返回 500。禁止让参数、方法、媒体类型或路径错误落到兜底的 500，否则前端会显示成"服务器错误"，Prometheus 的 5xx 指标也会被污染。

| 场景 | HTTP | code |
| --- | --- | --- |
| 请求体字段校验失败（`@Valid` / `@Validated`） | 400 | 1001 |
| 查询参数约束失败（`ConstraintViolationException`） | 400 | 1001 |
| 缺少必填查询参数 | 400 | 1001 |
| 查询参数类型或格式不合法 | 400 | 1001 |
| 请求体 JSON 无法解析 | 400 | 1001 |
| 未认证（无/非法/过期 Token） | 401 | 1002 / 1100 / 1101 |
| 权限不足或数据范围越权 | 403 | 1003 |
| 接口路径不存在 | 404 | 1004 |
| HTTP 方法不支持 | 405 | 1005 |
| 请求内容类型不支持 | 415 | 1008 |
| 业务异常（余额不足、状态冲突、重复请求等） | 200 | 2000+ |
| 未预期的服务端故障 | 500 | 1000 |

业务异常沿用项目既有的「HTTP 200 + 业务码」风格，前端拦截器统一按 `code` 判断；其余客户端错误返回 4xx，`message` 必须是可直接展示给用户的中文说明（例如"缺少必填参数：from"），由 `utils/request.ts` 直接弹出。

回归测试见 `FitnessApplicationIntegrationTest#malformedRequestsYieldActionableClientErrorsInsteadOfServerErrors`。

## 六、权限控制

### 6.1 角色定义

- `SUPER_ADMIN`：超级管理员
- `MANAGER`：场馆经理
- `SALES`：销售人员
- `RECEPTION`：前台员工
- `COACH`：教练
- `MEMBER`：会员

### 6.2 权限注解使用

```java
@PreAuthorize("hasRole('MANAGER')")
@PreAuthorize("hasAuthority('MEMBER_VIEW')")
@PreAuthorize("hasAnyRole('MANAGER', 'SALES')")
```

### 6.3 数据权限

通过 `SecurityUtil.getCurrentOrganizationId()` 获取当前用户所属场馆，在查询时自动过滤数据。

## 七、数据库设计

### 7.1 表命名规范

- 使用小写字母和下划线
- 表名使用复数形式（如 `members`、`bookings`）
- 关联表使用下划线连接（如 `role_permission`）

### 7.2 字段命名规范

- 使用小写字母和下划线
- 主键统一使用 `id`
- 外键使用 `{表名}_id` 格式
- 时间字段：`created_at`、`updated_at`

### 7.3 索引规范

- 主键自动创建索引
- 外键字段创建索引
- 经常用于查询条件的字段创建索引
- 联合索引用于复合查询条件

## 九、部署说明

### 9.1 后端部署

1. 打包：
```bash
mvn clean package -DskipTests
```

2. 运行：
```bash
java -jar target/fitness-backend-1.0.0.jar
```

### 9.2 前端部署

1. 构建：
```bash
npm run build
```

2. 部署 `dist` 目录到Nginx或静态服务器

### 9.3 环境变量配置

生产环境必须配置：
- `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`
- `JWT_SECRET`（必须修改默认值）

## 十、常见问题

### Q1: QueryDSL代码生成失败？
A: 执行 `mvn clean compile` 重新生成。

### Q2: 前端请求跨域问题？
A: 检查 `SecurityConfig` 和 `WebMvcConfig` 中的CORS配置。

### Q3: 数据库迁移失败？
A: 检查Flyway配置和SQL语法，查看日志定位问题。
