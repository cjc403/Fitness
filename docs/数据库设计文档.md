# 数据库设计文档

## 一、数据库概述

- **数据库类型**：PostgreSQL 16
- **字符集**：UTF-8
- **命名规范**：小写字母+下划线
- **迁移工具**：Flyway

## 二、核心实体关系

### 2.1 ER关系图

```
venue (场馆)
  ├── sys_user (系统用户)
  │   ├── member (会员)
  │   │   ├── member_card (会员卡)
  │   │   ├── member_package (会员套餐)
  │   │   └── member_points (积分记录)
  │   └── course_schedule (排课)
  │       └── booking (预约)
  │           └── attendance (出勤)
  ├── course (课程定义)
  ├── locker (储物柜)
  └── contract (合同)
```

## 四、索引设计

### 4.1 主要索引

- `idx_user_venue`：用户表场馆索引
- `idx_member_venue`：会员表场馆索引
- `idx_booking_schedule`：预约表排课索引
- `idx_booking_member`：预约表会员索引
- `idx_schedule_time`：排课表时间索引
- `idx_audit_entity`：审计日志实体索引

### 4.2 唯一索引

- `venue.code`：场馆编码唯一
- `sys_user.username`：用户名唯一
- `member.member_no`：会员编号唯一

## 五、数据权限设计

### 5.1 数据隔离策略

- 所有业务表都包含 `venue_id` 字段
- 查询时自动过滤当前用户的 `venue_id`
- 跨场馆操作需要特殊权限（SUPER_ADMIN）

### 5.2 软删除策略

- 关键表使用 `status` 字段标记删除
- 历史数据保留在 `audit_log` 表中

## 六、数据迁移

### 6.1 迁移脚本管理

- 使用Flyway进行版本控制
- 脚本命名：`V{version}__{description}.sql`
- 不可修改已执行的迁移脚本

### 6.2 初始化数据

- 默认角色数据
- 默认场馆（总部）
- 系统管理员账号（需手动创建）

## 七、性能优化建议

1. **查询优化**
   - 避免全表扫描
   - 合理使用索引
   - 分页查询限制返回数量

2. **连接优化**
   - 使用连接池（HikariCP）
   - 避免N+1查询问题

3. **缓存策略**
   - 权限信息缓存
   - 字典数据缓存

## 八、数据备份与恢复

### 8.1 备份策略

- 每日自动备份
- 备份保留30天
- 重要操作前手动备份

### 8.2 恢复流程

1. 停止应用服务
2. 恢复数据库备份
3. 执行必要的迁移脚本
4. 验证数据完整性
5. 重启应用服务

## 七、V10–V15 新增表结构（2026-09-30 补）

> 这份文档此前停在 2026-09-22（V9 时期）。以下按迁移顺序补齐 V10–V15 的表与关键列，**字段以迁移脚本为准**。

### 7.1 销售幂等与门禁令牌（V10）

| 对象 | 说明 |
| --- | --- |
| `sales_order.idempotency_key` / `request_fingerprint` | 开卡的幂等键与请求指纹；唯一约束 `uk_sales_order_operator_idempotency(operator_id, idempotency_key)`。同键同内容返回原单，同键不同内容拒绝 |
| `access_grant` | 门禁**一次性令牌**：`token`（唯一）、`member_id`、`venue_id`、`issued_at`、`expires_at`（60 秒）、`used_at`。取代了原先的永久会员令牌 |

### 7.2 站内通知与课程评价（V10 / V11）

| 表 | 关键列 |
| --- | --- |
| `notification` | `recipient_user_id`、`category`、`title`、`content`、`read_at`、`ref_type`、`ref_id`（用于定时提醒去重，例如 `ENTITLEMENT_EXPIRY_7`） |
| `course_review` | `booking_id`（**唯一**）、`member_id`、`course_id`、`schedule_id`、`coach_id`、`venue_id`、`rating`。只允许评价状态为 `ATTENDED` 的预约 |

### 7.3 优惠券（V11）

| 表 | 关键列 |
| --- | --- |
| `coupon_template` | 券模板：门槛、面额/折扣、有效期、可发放门店 |
| `member_coupon` | 会员持有的券；核销状态 |
| `sales_order.member_coupon_id` / `discount_cents` | 订单使用的券与抵扣额（`original=标价`、`paid=折后`、`discount=抵扣`；价值账按 `paid` 入账，**退款按实付**） |

### 7.4 教室与场地（V12）

| 对象 | 关键列 |
| --- | --- |
| `room` | `venue_id`、`name`、`capacity`、`status`(ACTIVE/INACTIVE)、`note`；索引 `idx_room_venue(venue_id, status)` |
| `course_schedule.room_id` | 排课指定教室；索引 `idx_schedule_room_time(room_id, scheduled_start_time)`。为空表示未指定教室 |

### 7.5 会籍跟进（V12）

| 表 | 关键列 |
| --- | --- |
| `member_follow_up` | `member_id`、`staff_user_id`、`venue_id`、`follow_type`(CALL/WECHAT/VISIT/OTHER)、`content`、`next_follow_at`；索引 `(member_id, id desc)`、`(staff_user_id, id desc)`、`(next_follow_at)`。配合既有 `member.sales_user_id` / `member.coach_id` 支撑会籍工作台 |

### 7.6 体测与训练档案（V13）

| 对象 | 关键列 |
| --- | --- |
| `body_measurement` | `member_id`、`venue_id`、`measured_on`、`weight_kg`、`body_fat_rate`、`muscle_kg`、`chest_cm`、`waist_cm`、`hip_cm`、`resting_heart_rate`、`note`、`recorded_by`；**唯一约束 `uk_body_measure_member_day(member_id, measured_on)`**（同一天重复提交视为修正，曲线不出现重复点） |
| `member.training_goal` / `training_goal_note` | 训练目标（FAT_LOSS / MUSCLE_GAIN / POSTURE / ENDURANCE），空表示未设置 |

### 7.7 消息投递（V14）

| 表 | 关键列 |
| --- | --- |
| `message_delivery` | `channel`(IN_APP/SMS/EMAIL)、`category`、`recipient_masked`（**只存脱敏后的收件人**，完整手机号/邮箱不落库）、`recipient_user_id`、`member_id`、`venue_id`、`subject`、`content`、`status`(SENT/FAILED/SKIPPED)、`provider`（`MOCK` = 模拟发送）、`provider_message_id`、`error` |

### 7.8 跨店适用范围（V15）

| 对象 | 关键列 |
| --- | --- |
| `product_venue` | `product_id`、`venue_id`，唯一 `uk_product_venue(product_id, venue_id)`。**表里没有记录 = 仅限商品所属门店**（向后兼容） |
| `member_entitlement.venue_scope` | 开卡时定格的适用门店快照（逗号分隔 venue id）。发卡门店永远可用；之后再改商品不影响已售出的卡 |

### 7.9 跨店模型的两条边界（重要）

1. **商品归属门店 = 收款方（发卡门店）**；`product_venue` 只声明"哪些门店的会员可以买、可以在哪些门店用"。
2. **退款与价值账分摊仍按发卡门店结算**——钱是谁收的退给谁，未跨店分摊；跨店升级补差价不在当前范围内。
