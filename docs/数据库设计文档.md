# 数据库设计文档

## 一、数据库概述

- **数据库类型**：PostgreSQL 16
- **字符集**：UTF-8
- **命名规范**：小写字母+下划线
- **迁移工具**：Flyway

## 二、核心实体关系

### 2.1 ER关系图

```
venue (场馆)
  ├── sys_user (系统用户)
  │   ├── member (会员)
  │   │   ├── member_card (会员卡)
  │   │   ├── member_package (会员套餐)
  │   │   └── member_points (积分记录)
  │   └── course_schedule (排课)
  │       └── booking (预约)
  │           └── attendance (出勤)
  ├── course (课程定义)
  ├── locker (储物柜)
  └── contract (合同)
```

## 三、核心表结构

### 3.1 场馆表 (venue)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键 |

| contact_phone | VARCHAR(20) | 联系电话 |
| status | VARCHAR(20) | 状态（ACTIVE/INACTIVE） |

### 3.2 系统用户表 (sys_user)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键 |

## 四、索引设计

### 4.1 主要索引

- `idx_user_venue`：用户表场馆索引
- `idx_member_venue`：会员表场馆索引
- `idx_booking_schedule`：预约表排课索引
- `idx_booking_member`：预约表会员索引
- `idx_schedule_time`：排课表时间索引
- `idx_audit_entity`：审计日志实体索引

### 4.2 唯一索引

- `venue.code`：场馆编码唯一
- `sys_user.username`：用户名唯一
- `member.member_no`：会员编号唯一

## 五、数据权限设计

### 5.1 数据隔离策略

- 所有业务表都包含 `venue_id` 字段
- 查询时自动过滤当前用户的 `venue_id`
- 跨场馆操作需要特殊权限（SUPER_ADMIN）

### 5.2 软删除策略

- 关键表使用 `status` 字段标记删除
- 历史数据保留在 `audit_log` 表中

## 六、数据迁移

### 6.1 迁移脚本管理

- 使用Flyway进行版本控制
- 脚本命名：`V{version}__{description}.sql`
- 不可修改已执行的迁移脚本

### 6.2 初始化数据

- 默认角色数据
- 默认场馆（总部）
- 系统管理员账号（需手动创建）

## 七、性能优化建议

1. **查询优化**
   - 避免全表扫描
   - 合理使用索引
   - 分页查询限制返回数量

2. **连接优化**
   - 使用连接池（HikariCP）
   - 避免N+1查询问题

3. **缓存策略**
   - 权限信息缓存
   - 字典数据缓存

## 八、数据备份与恢复

### 8.1 备份策略

- 每日自动备份
- 备份保留30天
- 重要操作前手动备份

### 8.2 恢复流程

1. 停止应用服务
2. 恢复数据库备份
3. 执行必要的迁移脚本
4. 验证数据完整性
5. 重启应用服务
