# 私教预约、签课消课与教练月结（2026-09-17）

## 五种角色在哪里使用

| 角色 | 页面与职责 |
| --- | --- |
| 总部管理员 | 会籍与商业 → 私教消课与结算；查看全门店、设定提成、生成和审核月结、办理未结算纠错 |
| 店长 | 同上，仅本门店；管理提成规则与审核，不允许跨门店操作 |
| 教练 | 教练工作台下方 → 私教消课与月结；本人签到、课程结束后提交授课、查看本人提成与月结 |
| 前台 | 销售私教课包、代预约时选择会员课包、签到、查看本店签课进度；不能代会员签课、冲正或审核月结 |
| 会员 | 会员中心 → 发现课程选择私教课包预约 → 私教签课；课程结束且教练提交后，本人确认扣 1 次 |

## 初学者演示步骤

1. 登录前台或管理员。在“销售与开卡”为会员购买有效私教课包。
2. 总部或店长在课程与排课里创建私教课程，分配本店有效教练，设置未来时间。过去的排课不能新预约。
3. 会员发现课程，点击私教预约，选择覆盖上课日期、还有可用次数的课包。前台也能代预约并明确选包。
4. 预约仅预占一次：**可预约次数 = 未消耗次数 − 预占次数**，此时不产生实际授课提成。
5. 会员到课后，教练或前台签到。课程结束后，教练在私教列表点击“提交授课”。
6. 会员本人点击“确认签课”，系统正式扣一次，保存该次课时金额和提成比例。重复点击不会重复扣次。
7. 店长选择教练和月份生成月结草稿；后来同月签课可再次更新草稿，审核时也会补齐同月记录。当前月尚未结束，只能生成草稿；次月才可审核。签课按服务器确认月份归属，因此迟签归到实际确认月，不追溯修改已审核旧月。
8. 已审核月结单表示系统账目确认，**不代表工资已经支付**；本阶段没有银行转账或工资打款功能。

不要为了演示修改真实服务器课程时间或对真实订单反复退款。自动验收在隔离测试数据库执行。

## 关键规则

- 开课前至少两小时，会员可取消或请假；释放预占，不扣课。更临近开课只允许总部或店长填写原因后办理。
- 爽约记录处罚并释放预占，不自动扣私教课包。入场二维码也不扣私教课次，即便该产品允许入场。
- 候补不预占课包。名额释放时重新检查会员状态和课包，失效候补标记取消并留原因，继续检查下一位；不会使原会员取消失败。自动递补优先选择最早到期有效私教课包。
- 有未结束预约或待签课的课包不能冻结、转卡或退款。已正式消课的课包也不能走原来的整包退款入口，需后续设计按剩余服务价值退款。
- 续费按未消耗课次余额和新增金额加权更新课时单价；签课时保存金额快照，已签课记录不被后来续费或修改提成重算。课时金额按分四舍五入，不作为精确会计结转功能。
- 默认私教提成 40%，总部和店长可设置 0–100%，保留两位小数。会员 API 不返回员工提成，不能读取月结。
- 未进入任何月结的待签课或已签课可由总部、店长填写理由冲正：待签课释放预占，已签课恢复一次。已经进入草稿或审核单均不能直接冲正；本阶段没有整单撤销和结算后财务调整入口。
- 所有新动作写入权益操作记录。历史未关联预约不自动绑定、不补扣课、不生成实际私教提成。
- 教练工作台产值与提成现在来自实际已签课的私教记录，累计展示；不再把签到人数乘课程标价当成已赚取金额。团课结算另行开发。

## 数据库与开发说明

新增 Flyway V8：会员权益预占字段、课时单价、私教记录、教练提成规则、月结单；V1–V7 保持不变。
每个预约最多一条私教生命周期记录，每位教练每门店每月份最多一张月结单。
本门店预约与签课采用门店 → 排课 → 教练（必要时）→ 课包的行锁顺序；月结只锁教练，不反向等待课包，以避免候补交换课包的锁顺序冲突。当前按门店串行写预约，适合学习规模，较大并发时需要进一步优化锁粒度和压测。

开发入口：后端 `module/training`，前端 `components/TrainingPanel.vue` 和 `api/modules/training.ts`。
验收：后端 Maven 集成测试、前端类型检查和生产构建、隔离 PostgreSQL 迁移和业务验收、生产只读五角色接口检查。
部署流程必须先备份数据库和旧版本，再发布，验证失败恢复旧应用；V8 为兼容性新增结构，应用回滚不自动删表或还原用户业务数据。

## 本阶段边界与后续方向

暂未接入真实支付或工资打款，不具备正式电子签名合同、结算后调整、按消费价值部分退款、私教专属教练绑定、多课时一次扣减等功能。会员签课是本人登录账号确认，并非司法意义的电子签章。
下一步优先：结算调整单、部分退款金额核算、精确剩余金额与尾差处理、消息提醒、报表导出；部署侧继续完善域名 HTTPS、备份异地保存和恢复演练。
