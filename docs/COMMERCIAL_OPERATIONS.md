# 商业健身房核心业务说明

## 本阶段完成内容

系统已经形成“商品配置 → 销售收款 → 自动开卡 → 权益履约 → 续费/冻结/转卡/退款 → 财务与单据 → 经营统计”的完整链路，并将课程预约扩展为包含候补、请假、爽约和教练业绩的真实业务流程。

### 会籍商品

- 期限卡：月卡、季卡、年卡，不限制有效期内入场次数。
- 次卡：按实际入场自动扣减次数。
- 私教课包：按课时计次，不作为门禁凭证。
- 商品支持按场馆隔离、售价、有效期、次数、上架状态和入场权限配置。

### 会员权益生命周期

- 销售开卡：收款后自动创建订单、会员权益、支付流水、合同和收据。
- 续费：顺延有效期，可同时增加次卡或课包次数，并生成续费收款流水和收据。
- 冻结/解冻：冻结期间不可入场；解冻时按冻结天数自动顺延有效期。
- 转卡：只允许转给同场馆、状态正常且未被拉黑的其他会员。
- 退款：校验订单可退金额，支持部分退款和全额退款，生成独立退款流水。
- 提醒：支持已到期、7 天内到期、30 天内到期和剩余次数不足四类提醒。

### 财务和单据

- 订单保存标价、实收、累计退款、支付渠道、经办人和状态。
- 支付流水区分收款与退款，支持微信、支付宝、银行卡和现金。
- 开卡自动生成合同与收据；订单可补开发票并记录抬头和税号。

### 二维码门禁

- 会员工作台展示可实际扫码的个人二维码。
- 前台或店长在“会籍与商业中心 → 二维码入场”核验。
- 期限卡校验有效期；次卡核验后自动扣减 1 次；私教课包不作为入场依据。
- 黑名单、暂停会员、无有效权益或无效二维码会被拒绝，并保留拒绝原因。
- 离场扫码不会扣减次数。

### 课程履约与教练业绩

- 团课满员后会员可加入候补；有人取消或请假时第一位候补自动转为已预约。
- 会员可在开课 2 小时前请假或取消。
- 教练只能为本人课程签到或标记爽约，爽约会累计处罚积分。
- 教练工作台区分待参加、已签到和爽约学员，显示完成课次、履约时长、服务产值与估算提成。
- 估算提成采用演示规则：私教 40%、常规课程 20%、团课 15%；正式使用时应改为可配置的劳动合同规则。

## 五角色演示路径

1. 总部管理员：登录后进入“会籍与商业”，查看两家门店商品、订单、权益、财务与入场汇总，也可选择场馆创建商品。
2. 店长：只查看和办理本场馆的商品、销售、权益、财务、退款、发票及门禁业务。
3. 前台：办理会员销售开卡、续费、冻结/解冻、转卡、退款、开票及扫码入场。
4. 教练：进入“教练工作台”，查看本人私教/团课、学员履约状态、课时、产值和估算提成，并处理签到或爽约。
5. 会员：进入“会员中心”，查看自己的会员卡/课包、到期与余次提醒、入场二维码，并进行课程预约、候补、请假和取消。

## 数据与安全边界

- PostgreSQL 迁移版本为 `V7__commercial_core.sql`，原有账号、会员、课程和预约数据会保留。
- 总部可查看全部场馆；店长和前台只能处理所属场馆数据；教练只能处理自己的课程；会员只能查看自己的权益与二维码。
- 所有金额、权益状态变化、付款退款和入场结果均落库留痕，便于后续增加审计、电子合同和真实支付渠道。

## 当前版本边界

当前合同、收据和发票为业务记录，并未对接电子签章、税控平台或真实支付网关；教练提成为可解释的演示估算。下一阶段可在现有订单号、流水号和单据号基础上接入第三方服务，而不需要重做核心数据模型。
