# 私教消课两端空白 —— 诊断与修改建议

状态：**仅诊断，未做任何代码改动**（按要求等你确认）。
用户反馈：管理端「会籍与商业中心 → 私教消课与结算」和会员端「会员中心 → 私教签课」都是空白，
会员也不知道这个功能怎么用。

## 一、这个功能本来是怎么跑的

```
① 会员预约私教课  →  ② 到店签到  →  ③ 教练提交  →  ④ 会员签课  →  正式消课（扣 1 次）
   （产生预占/记录）                                     （确认后才扣次）
```

代码路径：会员预约一节 `type = PRIVATE` 的课，`TrainingService.reserve(booking, schedule, requestedId)`
会创建一条 `private_lesson`（状态 `RESERVED`）。之后 `submit → confirm` 才真正扣次。

**这条链路有 4 个硬前置条件**（`TrainingService.java` 第 44–62 行）：

| # | 条件 | 不满足时的报错 |
| --- | --- | --- |
| 1 | 课程类型必须是 **私教课**（`course.type = PRIVATE`） | 非私教课直接跳过，不产生记录 |
| 2 | 该排课**必须已绑定教练账号**（`coach_id` 指向同门店、在职、角色为教练的用户） | 「私教课程尚未分配教练」/「私教课程的教练账号不可用」 |
| 3 | 会员须持有 **私教课包**（`PRIVATE_PACKAGE`），同门店、生效中、**有效期覆盖上课日期**、有剩余次数 | 「请先购买有效私教课包，再预约私教」 |
| 4 | 门店隔离：会员只能预约本人所属门店的排课 | 该排课不在会员列表里 |

## 二、为什么两端都是空白

### 结论：**不是 bug**。是「前置条件一个都没满足 + 从来没有过数据 + 界面没有任何引导」三件事叠加。

### 证据 1：接口和权限完全正常

| 角色 | `GET /api/v1/training/lessons` |
| --- | --- |
| admin | HTTP 200，code 0，**0 条** |
| coach | HTTP 200，code 0，**0 条** |
| cjc2（会员） | HTTP 200，code 0，**0 条** |

三个角色都能正常访问、只是没有数据。**与「会员退款」那次不一样**——那次是权限没配、接口直接 403。
所以这次**不需要动权限矩阵**。

### 证据 2：`private_lesson` 表里 0 条记录

这个流程**从未被跑通过一次**，所以"已预占 0 / 待会员签课 0 / 已正式消课 0"是真实数据，不是显示故障。

### 证据 3：会员端根本没有私教课可约（最直接的原因）

会员端「发现课程」当前只有 3 节，全都不是私教：

| 课程 | 类型 |
| --- | --- |
| 动感单车 | 团课 GROUP |
| 活力燃脂操 | 团课 GROUP |
| 功能性力量 | 常规课 REGULAR |

数据库里私教课只有 2 门：

| 课程 | 门店 | 排课情况 |
| --- | --- | --- |
| 一对一体态评估 | 总部 | **一条排课都没有** |
| 私教体验课 | 滨江店 | 2 条：一条 9/16 已过期、一条 9/26，**且两条的教练都是空的** |

总部会员 cjc2 看到的排课只限总部，而总部**私教排课数 = 0** →
**会员在界面上根本无法发起私教预约**，这条链路第一步就走不下去。

### 证据 4：cjc2 名下没有私教课包

cjc2 的 6 份权益全是期限卡/次卡：年度畅练卡×2、无限年卡、活力月卡、进阶季卡、健身 20 次卡。
**没有任何 `PRIVATE_PACKAGE`（私教课包）**。全库只有另外两位会员（苏洁、沈玥）各持一份。

即便有私教课可约，也会被第 3 条前置条件拦下。

### 证据 5：滨江店那两条遗留排课的教练是空的

`coach_id` 为空 → 预约时会直接报「私教课程尚未分配教练」。
（这正是我们前面修过的问题：排课的教练必须是**真实账号**，只填姓名不算。）

### 证据 6：界面没有告诉用户"下一步该做什么"

两个面板顶部只有一行小字说明：
「仅关联课包的私教预约进入本流程；历史预约不会自动扣课。爽约只释放预占，不自动扣次。」
它只解释了规则，**没有告诉会员"先买课包、再约私教课"，也没有告诉管理员"先建私教课、排课、绑教练"**。
所以会员看到空白表格完全不知道怎么办 —— 这一条是所有问题里最该改的。

## 三、修改建议

### A. 先让它跑起来（纯配置动作，不动代码，10 分钟内可验证）

1. **给总部的私教课排课并绑定教练**：「课程与排课」→ 用它给「一对一体态评估」新增一次排课，
   教练**必须从下拉里选真实教练账号**（这是关键，否则会员一约就报错）。
2. **给 cjc2 开一份私教课包**：现在会员可以自助购买，让 cjc2 在「购买会籍」里买「私教 12 节课包」即可；
   或管理员在「销售与开卡」里开。
   注意课包**有效期必须覆盖上课日期**、门店要和排课门店一致。
3. **补绑滨江店那两条遗留私教排课的教练**：用「编辑」选一次教练账号。

做完这三步，会员端就能完整走一遍：预约私教课 → 预占 1 次 → 前台签到 → 教练提交 → 会员签课 → 正式消课。

### B. 代码改进建议（按我建议的优先级，等你点头再动）

| 优先级 | 建议 | 说明 | 改动范围 |
| --- | --- | --- | --- |
| **P0** | **两端面板加"当前卡在哪一步"的引导** | 会员端：没有私教课包 → 显眼提示并给「去购买会籍」按钮；有课包但本门店无私教排课 → 提示"本门店暂未开放私教排期，请联系前台"。管理端：0 条记录时列出 4 条前置条件清单，并显示本门店「私教课程数 / 私教排课数 / 已绑教练的排课数」。 | 前端为主，`TrainingPanel.vue` |
| **P1** | **会员端加「去预约私教课」入口** | 从「私教签课」直接跳到「发现课程」并**只筛出私教课**。现在私教课混在团课列表里，只有一个小标签，会员很难发现。 | 前端 `MemberHome.vue` |
| **P2** | **无教练的排课在管理端给出警示** | 「课程与排课」列表里，私教课若没绑定教练，用醒目标记提示——否则建完排课以为好了，会员一约就报错。 | 前端 + 可能后端返回标记 |
| **P3** | **预留课包与排课的匹配校验前置** | 建私教排课时，如果本门店沒有任何私教课包可卖/在售，给管理员一个提示（避免建了排课却没人能约）。 | 后端小改 |

### C. 我不建议做的事

- **不建议放宽"必须有私教课包才能约私教"这条规则**。这是私教消课的资金闭环基础（预占 → 签课 → 扣次），
  放开会让消课失去依据。
- **不建议为了看到效果而直接往库里塞 private_lesson 数据**。这条链路涉及预占与扣次，
  造假数据会污染价值账；走一遍真实流程只要 3 步配置。
