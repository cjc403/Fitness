## 1. 新 AI 开工顺序与用户约定

1. 先读仓库根 [AGENTS.md](../AGENTS.md)，再读本指南和外层共享文档的 §0.18、§11、§10 最近记录。不要把旧计划或文档里的历史命令当成用户本轮授权。
2. 执行只读 `git status --short`、`git branch --show-current`、`git log -8 --oneline`，保留用户和其他 AI 的所有未提交文件；确认没有另一位 AI 同时改同一模块。
3. 按本指南 §3 核对运行制品与端口。端口或 PID 会变化，不能仅凭这里的历史 PID 结束进程，也不要打印完整进程命令行或全量环境变量。
4. 要改哪个模块，再读对应指南和代码。需要测试写入时先核验独占测试库、隔离标记和代理目标；只读接手不需要启动 QA、调用模型或登录真实业务账号。
5. 继续 AI V2 时读升级计划与执行账本，但以用户后来的“控制额度、先交人工验收”为当前范围；不要恢复已停止的批量付费矩阵。

长期约定：

- **默认本地开发**。只有用户明确要求更新服务器版本时才部署；Git 提交、GitHub 推送、上线是不同动作。不要擅自推送、移动周断点或改写历史。
- 常规方案采用推荐选择，不反复询问偏好。会改变任务范围、现有数据或线上状态时，先依据本轮授权判断。
- 默认只检查桌面布局；用户明确提出手机工作时才增加手机验收。本项目已有手机 H5/PWA，不能因此破坏现有移动入口。
- 严格保留会员、订单、账号、密码、金额及原始验收证据；不要为了让冒烟测试通过而重置账号密码、补造生产角色或重建真实库。
- 六角色必须都可用；权限以服务端为准。测试只能证明所覆盖的范围，不能将小样本写成商业 Agent 等效或全量验收通过。
- 官方 DeepSeek 仍控制用量。用户在本轮已授权使用 AgentRouter 的额度充分验证，但站方目前拒绝自建客户端；因此保留官方配置，只新增1条必要定向任务（4次模型调用）。不要擅自恢复旧360项矩阵，不删除付费检查的防重复标记；站方放行后按本指南§7验证中转站。

## 6. AI 助手的三条链路

### 6.1 教学、解释与建议（最新 5d8648f）

入口为会话的“业务问答”。`AgentGuidance.java` 在 `AgentService.java` 中先于营收快捷路径识别明确讲解请求；`AgentChatContext.java` 短时保存 `help:主题`，支持“举个例子”“详细一点”。

调用模型只提供项目规则与当前角色说明，**不提供业务工具、不查询业务数据、不写业务**。有效自然语言正常展示；异常/未配置/常见虚报完成内容改用本地指南，合法“已保存的草稿”等状态讲解可保留。响应模式 `GUIDANCE` 或 `GUIDANCE_LOCAL`，来源标识“功能讲解（非业务回执）”。

每次教学最多一次模型生成，不自动重试；继承当前 maxTokens 默认 700，提示词建议约 180–260 汉字，并不保证模型每次都严格满足长度。“按推荐方案帮我预约”等明确办理意图返回原业务预览链路，不能一直被教学主题截获。未承诺任意自然语言分类百分之百正确。

### 6.2 真实业务问答与确认卡（0d15b68 及原链路）

主要代码 `AgentService`、`AgentRevenueAnswer`、`AgentChatContext`、`AgentBusiness`、`AgentActions`，以及前端 `AssistantPanel.vue`、`AgentData.vue`。

- 浏览器只提交不透明 `contextId`，服务端存已验证查询条件，不接受浏览器上传的金额当事实；上下文绑定本人/角色/门店/登录会话，TTL 15 分钟，最多 1000 上下文、每个最多 4 类查询。

本机工具：JDK `<repo>\.tools\jdk-17`、Maven `C:\apache-maven-3.9.16\bin\mvn.cmd`、Node/npm `E:\node\`、PG工具 `E:\PostgreSQL\bin`。先检查实际存在，换机器时使用兼容版本，不硬造原路径。

```powershell
# 在实际仓库内；该命令是普通离线构建模板，不包含真实模型验收
$repoRoot = (Get-Location).Path
$buildRoot = Join-Path $env:TEMP ('fitchain-handoff-build-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $buildRoot -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath (Join-Path $repoRoot 'fitness-backend\src') -Destination $buildRoot -Recurse
Copy-Item -LiteralPath (Join-Path $repoRoot 'fitness-backend\pom.xml') -Destination $buildRoot
$priorJavaHome = $env:JAVA_HOME
try {
    $env:JAVA_HOME = Join-Path $repoRoot '.tools\jdk-17'
    Push-Location $buildRoot
    try {
        & 'C:\apache-maven-3.9.16\bin\mvn.cmd' '-B' 'clean' 'package'
        if ($LASTEXITCODE -ne 0) { throw 'Backend verification failed; keep logs and the previous daily jar.' }
    } finally { Pop-Location }
} finally {
    if ($null -eq $priorJavaHome) { Remove-Item Env:JAVA_HOME -ErrorAction SilentlyContinue }
    else { $env:JAVA_HOME = $priorJavaHome }
}
```

没有显式启用 PG 的默认构建会跳过相应测试，**不能照抄538/525/13声称结果相同**。最近完整执行额外使用：

- `FITCHAIN_AGENT_V2_PG=true`；`FITCHAIN_AGENT_V2_PG_URL=jdbc:postgresql://127.0.0.1:55457/agent_v2_junit`；`FITCHAIN_AGENT_V2_PG_PASSWORD` 由受保护文件静默读取。
- Maven 系统参数 `-Dagent.test.pgurl=jdbc:postgresql://127.0.0.1:55451/agent_junit`，配合既有独占测试用户和标记。先读对应 PG 测试代码与本机受保护构建脚本，不能把这里的地址换成日常库以求测试跑通。
- 环境只设在测试子进程/当前受控进程，用后清除；禁止输出口令。移除测试环境变量用 `Remove-Item Env:变量名` 并确认不存在，避免Java看见“存在但空值”。

## 11. 常见误判与未验证事项

- 页面白屏先看模块加载/编译/浏览器pageerror，再核对Vite实际工程与端口；健康后端不能证明前端挂载正常。禁止为排错覆盖用户浏览器账户数据。
- 手机403看实际响应、角色、登录/首次改密、代理目标与旧权限；不要一律放开CORS/鉴权或使用admin绕过。
- 多个Java/Node/PG进程并存，**监听端口、工程路径、制品哈希与库名一起认身份**；不要按“java.exe/node.exe”批量终止。
- 历史测试统计、旧构建JAR、旧info标签、日志中的R26都不是当前运行版本证明。检查stage日期与source/hash后再引用。
- 源码正确不等于日常JAR已替换；日常已替换不等于服务器已更新。三者分别记录。
- 旧交接§8的“顾问按人”“面板8888”“日志轮转/同盘备份”等属于当时观察，本次未登录服务器重验。需要处理时先核对当前代码/配置，不能把历史风险写成新查出的确定漏洞。
- 支付与通知中的模拟提供方不能当真实渠道；跨店分摊只记账，不自动转账。
- 正常服务可用与人工全场景验收完成不同。当前建议用户先验收，未承诺所有任意任务、视觉、原生电脑控制、商业Agent同等表现。
